# Handoff: מסכי כניסה, הרשמה ואיפוס — CourtSide

## סקירה

הפריט הראשון ברשימת המסירה של הבעלים: **הדלת של המוצר**. בקוד יש כבר `Auth.jsx` ו-`ResetPassword.jsx` עובדים, אבל בדסקטופ-first ובלי כמה מסכים קריטיים (בחירת תפקיד, הצטרפות שחקן עם קוד, קלט קוד חד-פעמי כ-6 תאים, מצב «הקישור נשלח»). החבילה הזו מוסיפה 10 מסכים מובייל-first ב-390×844, בעברית RTL, ומגדירה איך הם נכנסים לתוך הזרימה הקיימת.

**היקף:** רק הדלת — כל מה שקורה לפני `session`. אין כאן שינוי ל-Dashboard, ל-PlayerDashboard או ל-Landing.

## על קבצי העיצוב

הקבצים ב-`design/` הם **אסמכתה עיצובית שנוצרה ב-HTML** — פרוטוטייפ שמראה את המראה וההתנהגות המיועדים. הם **אינם קוד לייצור ואין להעתיק מהם JSX**, לא לייבא אותם ולא לצרף אותם ל-build.

המשימה היא **לשחזר את העיצובים האלה בתוך הסביבה הקיימת של הריפו** — React 18 + Vite, Supabase Auth, `lucide-react`, `src/i18n.js`, וטוקני ה-CSS של `src/index.css` — לפי הדפוסים שכבר נהוגים שם. הפרוטוטייפ בנוי כמסמך אחד עם 10 מסכי טלפון זה לצד זה; הוא לא מייצג ארכיטקטורת רכיבים, רק את המצב הסופי של כל מסך.

`design/support.js` הוא רק ה-runtime שמריץ את הפרוטוטייפ בדפדפן. **התעלם ממנו לחלוטין.**

## נאמנות

**Hi-fi.** צבעים, טיפוגרפיה, מרווחים ורדיוסים סופיים ומדידים — כל הערכים במסמך הזה. יש לשחזר פיקסל-פרפקט, אבל **דרך הטוקנים והמחלקות הקיימות**, לא דרך ה-hex שבפרוטוטייפ (ראה «טוקנים ומיפוי צבע»). מה שלא hi-fi: מסגרת הטלפון (רדיוס 34px, גבול `#DCE4EF`, הצל) ושורת הסטטוס בגובה 46px — הן תפאורה של הפרוטוטייפ ולא חלק מהאפליקציה.

## מפת שילוב עם הקוד הקיים

זה החלק שקובע. `src/App.jsx` הוא השער: הוא מרנדר `Landing` → `Auth` → `Dashboard`, ומטפל בנתיבי `?reset=true` / `PASSWORD_RECOVERY` / `#/drill/<id>` / `#/join/<code>`.

| מסך | סטטוס | קובץ יעד | הערה |
|---|---|---|---|
| 1a בחירת תפקיד | **חדש** | `src/RolePicker.jsx` | מסך חדש לפני `Auth`. נכנס ב-`App.jsx` בענף «לא מחובר»: `Landing → RolePicker → Auth(role)`. שומר את הבחירה ב-`localStorage('signup_role')` ומעביר `role` כ-prop ל-`Auth`. |
| 1b כניסה | **מחליף** | `src/Auth.jsx` (`mode === 'signin'`) | אותו state, אותם handlers, פריסה חדשה. הטאבים, `link-button` של «שכחת סיסמה?», `auth-divider`, `btn-soft auth-otp-btn` ו-`auth-trust-inline` כולם קיימים — רק מעוצבים מחדש. |
| 1c הרשמה · מאמן | **מחליף** | `src/Auth.jsx` (`mode === 'signup'`) | מוסיף שדה שם מלא, מד חוזק סיסמה, בורר מועדון, וצ׳קבוקס הסכמה מפורש במקום `auth-consent` הטקסטואלי. שם ומועדון דורשים החלטה — ראה «החלטות פתוחות». |
| 1d הרשמה · שחקן עם קוד | **חדש** | `src/JoinWithCode.jsx` | מסך חדש. מתחבר למנגנון הקיים: `App.jsx:22` שומר `localStorage('pending_join_code')` מלינק `#/join/<code>`, ו-`PlayerDashboard.jsx:80-82` צורך אותו. המסך הזה הוא הקלט הידני לאותו מפתח, למי שלא הגיע מלינק. |

| 1f הקישור נשלח | **מחליף** | `src/Auth.jsx` (`message` אחרי `forgot`) | כרגע זו שורת `alert alert-success`. הופך למסך מלא עם «לא הגיע?», השהיית שליחה חוזרת וכפתור «שינוי המייל». צריך state חדש: `sentStep`. |
| 1g קוד חד-פעמי | **מחליף** | `src/Auth.jsx` (`mode === 'otp'`, `otpStep === 'verify'`) | ה-`input.otp-code` הבודד הופך ל-6 תאים. `cooldown` ו-`sendCode`/`verifyCode` נשארים כמו שהם. |
| 1h סיסמה חדשה | **מחליף** | `src/ResetPassword.jsx` | אותם `password`/`confirm`/`show`/`done`/`matchState`. מוסיף מד חוזק. שומר את ענף `linkError` הקיים (המצב שלו מופיע ב-1i). |
| 1i מצבים | **אסמכתה** | לא מסך | ספריית מצבים: טעינה, שגיאה, אופליין, שגיאת שדה. מיישמים אותה **בתוך** 1b–1h. אין לבנות מסך «מצבים» באפליקציה. |
| 1j כניסה · מצב כהה | **CSS** | `src/index.css` (append) | אותו DOM של 1b תחת `[data-theme="dark"]`. `App.jsx` כבר מחיל `data-theme` מ-`localStorage('theme')` לפני התחברות — אין צורך בלוגיקה חדשה. |

### שינויים ב-`App.jsx`

הענף היחיד שנוגעים בו הוא «לא מחובר» (סוף הקובץ). כרגע:

```
showAuth ? <Auth onBack={...} /> : <Landing onEnter={...} />
```

צריך שער נוסף לבחירת תפקיד לפני `Auth`, ומסלול לשחקן עם קוד. שאר השערים — `!supabaseConfigured`, `loading`, `isRecoveryMode`, `sharedDrill`, `session` — **נשארים בדיוק כמו שהם**. `isRecoveryMode` הוא זה שמרנדר את 1h; אין לשנות את הזיהוי שלו (`?reset=true` או אירוע `PASSWORD_RECOVERY`).

### מה נשאר לדסקטופ

`Auth.jsx` בנוי כ-`auth-split`: `auth-hero-panel` (תמונת מגרש + ציטוט מתחלף מ-`COACHING_QUOTES` כל 8 שניות) ליד `auth-form-panel`. **הפאנל נשאר.** העיצוב החדש הוא מה שקורה מתחת ל-breakpoint המובייל: הפאנל הצידי הופך לבאנר עליון (`height: 280px`) עם אותה תמונה, אותו גרדיאנט ואותו ציטוט. מעל ה-breakpoint — הפריסה הקיימת ממשיכה לעבוד. אין למחוק את `auth-hero-panel` ואין להסיר את סבב הציטוטים.

## מסכים

מידות משותפות לכל המסכים: מסך 390×844. גלולת התוכן הלבנה עולה 26px מעל הבאנר (`margin-top: -26px`), רדיוס `28px 28px 0 0`, `padding: 20px`, `box-sizing: border-box`, `gap` 13–16px. שורת סטטוס 46px היא תפאורה.

### 1a · בחירת תפקיד

**מטרה:** מפצל את הקהל בצעד הראשון. מאמן, שחקן והורה נכנסים לשלושה צינורות שונים.

**פריסה:** באנר תמונה 404px עם `object-position: 52% 42%` וגרדיאנט `linear-gradient(180deg, rgba(23,38,74,.58), rgba(10,20,40,.9) 60%, #0A1428)`; מעליו לוגו CourtSide (SVG כדור, 34px) + eyebrow «קהילת המאמנים של ישראל» ב-Heebo 800 11px `letter-spacing: .16em` בזהב, כותרת Heebo 900 35px/1.06 `letter-spacing: -.03em` לבנה בשתי שורות, ותת-כותרת Rubik 400 14.5px/1.6 בלבן 74%. הגלולה מכילה eyebrow «מי אתה במגרש?» ושלושה כרטיסי תפקיד.

**כרטיס תפקיד:** `display: grid; grid-template-columns: 46px 1fr 16px; gap: 13px`, רדיוס 20px, padding 15px, רקע לבן, גבול 1px. אייקון בריבוע 46px רדיוס 14px. שם ב-Heebo 800 17px, תיאור ב-Rubik 400 12.5px/1.45, שברון `ChevronBack` 16px בקצה.
**נבחר (מאמן):** גבול `1.5px` בכתום-כפתור + `box-shadow: 0 6px 18px -10px rgba(179,78,28,.35)`, ריבוע האייקון במלא כתום עם אייקון לבן.
**לא נבחר:** גבול 1px בקו, ריבוע האייקון ב-tint רך, אייקון בכתום-טקסט.
תג «צריך קוד מהמאמן» על כרטיס השחקן: Rubik 600 11px, גלולה ב-tint כתום רך, padding `3px 9px`.

**קופי:** מאמן — «בונה תוכניות אימון, מנהל קבוצות, שולח לשחקנים». שחקן — «מקבל משימות מהמאמן ועוקב אחרי היעדים שלו». הורה — «רואה מה קורה באימונים ומאשר את ההרשמה של הילד». תחתית: «כבר יש לך חשבון? כניסה» + «בהמשך אתה מאשר את תנאי השימוש ומדיניות הפרטיות» (קישורים ל-`/terms.html` ו-`/privacy.html` שכבר קיימים ב-`public/`).

**התנהגות:** לחיצה על תפקיד → `Auth` עם `role`. מאמן ושחקן חובה; הורה תלוי בהחלטה פתוחה #1.

### 1b · כניסה

**מטרה:** המסך שמזין את כל השאר. מייל+סיסמה כדרך ראשית, קוד-למייל כשנייה.

**פריסה:** באנר 280px (`object-position: 52% 38%`), לוגו 30px, כותרת Heebo 900 29px/1.1 «ברוך שובך למגרש» צמודה לתחתית הבאנר, ומתחתיה הציטוט: Rubik 500 13.5px/1.55 בלבן 78% + שם המחבר בזהב 600.

**רכיבים:**
- **טאבים** (`.tabs`): מסילה בגובה 50px רדיוס 999px padding 4px gap 4px; כל טאב 42px רדיוס 999px Heebo 15px. פעיל — רקע נייבי-1, טקסט לבן, משקל 800. כבוי — טקסט משני, משקל 700.
- **שדה קלט:** גובה **50px**, רדיוס **14px**, גבול `1.5px`, רקע משטח, `padding: 0 14px`, אייקון 18px ואחריו `gap: 10px`. הטקסט Rubik 400 15px, `dir="ltr"` + `text-align: start`. **פוקוס:** גבול נייבי-1 + `box-shadow: 0 0 0 3px rgba(23,38,74,.1)`. סיסמה מוסתרת: 17px `letter-spacing: .22em`. כפתור עין 36×36 רדיוס 10px (מתרחב ל-44px תחת `pointer: coarse`).
- **«שכחת סיסמה?»** — `link-button` בכתום-טקסט, Rubik 600 13px, מיושר לתחילת השורה, `margin-top: -4px`.
- **כפתור ראשי** (`.btn-primary`): גובה **52px**, רדיוס 14px, רקע כתום-מלא, טקסט לבן Heebo 800 17px, `box-shadow: 0 10px 20px -10px rgba(179,78,28,.6)`.
- **מפריד** (`.auth-divider`): קו 1px + «או» ב-Rubik 500 12px, `gap: 12px`.
- **כפתור משני** (`.btn-soft`): גובה 48px, רדיוס 14px, רקע משטח, גבול 1.5px, Heebo 700 15px, אייקון `KeyRound` 18px.
- **שורת אמון** (`.auth-trust-inline`): שלושה פריטים, `Check` 14px בירוק + Rubik 500 11.5px. flex עם `gap: 14px` ו-`flex-wrap`.

### 1c · הרשמה · מאמן

**מטרה:** פתיחת חשבון מאמן במסך אחד, בלי wizard.

**פריסה:** באנר 206px (`object-position: 52% 30%`) עם «חזרה לבחירת תפקיד» (`ChevronBack` בזהב + Rubik 700 12.5px) וכותרת Heebo 900 28px «פותחים חדר מאמנים». הגלולה: `gap: 13px`.

**שדות:** שם מלא · מייל · סיסמה + מד חוזק · מועדון (אופציונלי, בורר עם `ChevronDown` 17px) · צ׳קבוקס הסכמה · כפתור ראשי «יצירת חשבון» · «כבר רשום? לכניסה».

**מד חוזק:** תווית ימנית «חוזק: טובה» ב-Rubik 600 11.5px בירוק. פס בגובה **8px** רדיוס 999px, מסילה במשטח-משני, מילוי `linear-gradient(90deg, --brand-strong, --brand)` ברוחב 72%. מתחת: Rubik 400 11.5px «לפחות 8 תווים. אות גדולה או מספר עושים את ההבדל.» מיפוי: <8 תווים = חלש/אדום, 8+ = בסדר, 8+ עם אות גדולה או ספרה = טובה (72%), 12+ מעורב = חזקה (92%). **הוואלידציה בקוד היא 8 תווים** (`Auth.jsx`) — המד הוא משוב, לא חוק חדש.

**צ׳קבוקס הסכמה:** ריבוע 22px רדיוס 7px, מסומן = כתום-מלא + `Check` לבן 14px. טקסט Rubik 400 12px/1.55: «קראתי ואני מאשר את תנאי השימוש ומדיניות הפרטיות, כולל שמירת פרטי שחקנים בקבוצות שלי.» **חובה** — הכפתור הראשי חסום עד סימון.

### 1d · הרשמה · שחקן עם קוד

**מטרה:** שחקן שקיבל קוד מהמאמן מצטרף לקבוצה הנכונה בצעד אחד.

**פריסה:** מסך כהה מלא — תמונת מגרש ב-`opacity: .16` מעל רקע כהה + גרדיאנט `linear-gradient(180deg, rgba(15,20,30,.86), #0F141E 58%)`. כותרת Heebo 900 33px/1.08 «יש לך קוד מהמאמן?», הסבר Rubik 400 14px/1.6 בלבן 68%.

**תאי קוד:** 6 תאים **50×62px**, רדיוס 14px, `gap: 9px`, `dir="ltr"` על המכל, Heebo 900 26px לבן. מלא — רקע לבן 7% + גבול לבן 20%. פעיל — רקע כתום 14% + גבול כתום + קרסור 2×28px בהבהוב `1.1s step-end`. ריק — גבול מקווקו לבן 18%. מתחת: Rubik 400 11.5px «אותיות ומספרים · לא מבדיל בין גדולות לקטנות» — **הקוד אלפאנומרי** (`[A-Z0-9]{4,10}` לפי `App.jsx:19`), לא ספרות בלבד; נרמל ל-uppercase בקלט.

**פעולות:** «הצטרפות לקבוצה» (ראשי) · «סריקת קוד QR מהמאמן» (משני שקוף, `QrCode` 18px) · מפריד «או» · קישור «אין לי קוד — להירשם ולחפש קבוצה אחר כך». בתחתית באנר גילאים: «מתחת לגיל 16? נשלח אישור הורה למייל שתזין בשלב הבא — עד שההורה מאשר, המאמן לא רואה את הפרטים.»

**התנהגות:** קוד תקין → כתיבה ל-`localStorage('pending_join_code')` והמשך להרשמה; `PlayerDashboard` צורך אותו אחרי יצירת החשבון. QR הוא nice-to-have — אם אין ספריית סריקה, להסתיר את הכפתור, לא להציג כפתור מתפקד-למחצה.

### 1e · שכחת סיסמה

**פריסה:** באנר שטוח 150px בגרדיאנט `linear-gradient(160deg, --navy-1, --navy-2)` עם «חזרה להתחברות». תוכן `padding: 24px 20px 20px`, `gap: 16px`: כותרת Heebo 900 27px/1.15 «שכחת סיסמה? קורה.» · הסבר Rubik 400 14px/1.65 · שדה מייל (בפוקוס) · באנר רך בגוון כתום עם `Clock` 18px: «הקישור תקף לשעה אחת ולשימוש חד-פעמי. אם הוא פג — פשוט מבקשים חדש.» · כפתור «שליחת קישור איפוס» · «נזכרת בסיסמה? לכניסה» · כרטיס תחתון «נכנסת פעם עם קוד למייל?» עם קישור ל-1g.

**באנר סטטוס — תבנית קבועה:** רדיוס 14px, `padding: 13px 14px`, אייקון 18px `flex: none; margin-top: 1px`, `gap: 10px`, טקסט 12–12.5px/1.55 בגוון הכהה של המשפחה. **רקע רך + אייקון צבעוני — בלי גבול-צד** (חוק 4 ב-DESIGN.md).

### 1f · הקישור נשלח

**פריסה:** באנר 150px זהה. תוכן ממורכז, `padding: 34px 24px 20px`: עיגול 74px ברקע ירוק-רך עם אייקון מייל-מאושר 34px · כותרת Heebo 900 25px/1.2 «הקישור בדרך אליך» · פסקה עם המייל ב-`<bdi dir="ltr">` ומשקל 600 · כפתור «פתיחת תיבת המייל» · כרטיס «לא הגיע?» (רדיוס 20px, טקסט מיושר לימין) עם שתי נקודות בוליט ושני כפתורים בגובה 44px: «שליחה מחדש (57)» כבוי ו-«שינוי המייל» · הערת אבטחה בתחתית ב-Rubik 400 11.5px/1.6.

**קופי חשוב:** «מסיבות אבטחה אנחנו לא מגלים אם המייל קיים במערכת. אם אין חשבון — לא יישלח כלום.» זה תואם את ההודעה הקיימת ב-`Auth.jsx` (הגנת enumeration) — אל תשנה את ההתנהגות הזו.

### 1g · קוד חד-פעמי

**פריסה:** באנר 150px. כותרת «הקוד מהמייל» · «שלחנו שש ספרות ל-<מייל>. שינוי כתובת» · 6 תאים 50×62px רדיוס 14px על רקע לבן, גבול `1.5px` בגוון קו-כהה, Heebo 900 26px; פעיל — גבול כתום + `box-shadow: 0 0 0 3px rgba(179,78,28,.14)` + קרסור מהבהב; ריק — גבול מקווקו · באנר שגיאה אדום-רך: «הקוד שגוי או פג תוקף. אפשר לבקש קוד חדש בעוד 18 שניות.» · כפתור ראשי **כבוי** «אימות וכניסה» · שורה עם «שליחה מחדש (57)» מול «כניסה עם סיסמה» · כרטיס תחתון «גם הקישור במייל עובד».

**התנהגות:** הדבקה של 6 תווים מפזרת לתאים; Backspace בתא ריק חוזר אחורה; מלא = שליחה אוטומטית. הכפתור כבוי עד 4 תווים (כמו `code.length < 4` בקוד). `cooldown` מ-60 שניות אחרי `sendCode` — קיים, לא לשנות. `inputMode="numeric"` + `autoComplete="one-time-code"`.

### 1h · סיסמה חדשה

**פריסה:** באנר 150px עם לוגו CourtSide 26px. כותרת «סיסמה חדשה» · «בוחרים סיסמה שאתה יכול לזכור, ואנחנו נדאג שתישאר מחוברת» · שדה סיסמה חדשה עם עין פעילה (`EyeOff` בכתום-טקסט = מוצג) + מד חוזק 92% · שדה אישור עם גבול ירוק-רך ו-`Check` ירוק בקצה + שורת «הסיסמאות תואמות» (Rubik 600 12px ירוק, `Check` 13px) · כפתור «עדכון סיסמה» · «אחרי העדכון נכניס אותך לאפליקציה אוטומטית — בלי להקליד שוב» · באנר אזהרה תחתון על קישור פג-תוקף עם קישור ל-1e.

**התנהגות:** `matchState` קיים (`ok`/`bad`) — הגבול הירוק והצ׳ק הם התצוגה של `ok`. `bad` → גבול אדום + «הסיסמאות אינן תואמות», והכפתור חסום. אחרי הצלחה: `done`, הודעת הצלחה, ו-`setTimeout(goHome, 2500)` — קיים בקוד, לא לשנות. ענף `linkError` (`otp_expired` מה-hash) נשאר.

### 1i · מצבים

ספריית ההתייחסות. לא מסך באפליקציה.

- **טעינה:** הכפתור הראשי נשאר במקום, מתכהה לגוון לחוץ, טקסט «רגע...» + ספינר 17px (`border: 2.4px`, `animation: .8s linear infinite`). הטופס לא נעלם, אין קפיצת לייאאוט.
- **שגיאת התחברות:** באנר אדום-רך + `XCircle`. «מייל או סיסמה שגויים. אפשר לאפס דרך «שכחת סיסמה?».» — הטקסט הזה כבר קיים ב-`translateError`.
- **קישור פג:** באנר כתום-אזהרה + כפתור «שליחת קישור חדש» בגובה 42px רדיוס 12px. **לכל שגיאה יש דרך יציאה.**
- **אופליין:** באנר כחול-מידע: «אין חיבור לאינטרנט. שמרנו את מה שהקלדת וננסה שוב אוטומטית.» הקלט לא נמחק.
- **שגיאת שדה:** גבול אדום על הקלט + Rubik 500 12px מתחתיו: «כתובת המייל לא נראית שלמה — חסר סיום דומיין.» ההודעה ליד השדה, לא בתחתית המסך.
- **הצלחת הרשמה** מוצגת כמסך מלא (1f), לא כבאנר.

### 1j · כניסה · מצב כהה

DOM זהה ל-1b. הבדלים: רקע מסך כהה, משטחים כהים, מסילת טאבים במשטח-משני והטאב הפעיל במשטח כהה + `box-shadow: 0 2px 8px rgba(0,0,0,.35)`; גבולות בקו-כהה; פוקוס בכתום-טקסט-כהה + `box-shadow: 0 0 0 3px rgba(240,168,120,.16)`; התמונה ב-`opacity: .5`; צ׳קים בירוק-כהה. **הכפתור הראשי נשאר בדיוק אותו כתום בשני המצבים.**

## אינטראקציות והתנהגות

**זרימות:** `Landing → RolePicker(1a)` → מאמן: `Auth(signup, 1c)`; שחקן: `JoinWithCode(1d) → Auth(signup)`. `Auth(signin, 1b)` → «שכחת סיסמה?» → `1e` → `1f` → (מייל) → `1h` → אוטו-לוגין. `1b` → «קוד למייל» → `otp/request` → `1g`. חזרה בכל מסך פנימי → `signin`.

**מצבי פוקוס:** גבול + טבעת 3px, לעולם לא `outline: none` בלי חלופה. סדר טאב עוקב אחרי סדר ה-DOM. `Enter` בטופס = הפעולה הראשית.

**ואלידציה:** מייל — `type="email"` + בדיקת דומיין להודעת השדה; סיסמה — 8 תווים מינימום (הכלל הקיים); אישור סיסמה — השוואה חיה; קוד — 6 תווים אלפאנומריים ל-1d, 6 ספרות ל-1g.

**אנימציה:** מעברי UI 150–250ms `--ease-out`. מילוי מד חוזק עד 600ms. הבהוב קרסור `1.1s step-end`. ספינר `.8s linear`. הכל מכובה ב-`prefers-reduced-motion: reduce` וב-`html.a11y-motion`.

**רספונסיביות:** העיצוב הוא 390px. עד 480px — עמודה אחת ברוחב מלא. מעל ה-breakpoint — הפריסה המפוצלת הקיימת ממשיכה, והבאנר חוזר להיות פאנל צד.

## ניהול state

הכל קיים ב-`Auth.jsx` — `mode` (`signin|signup|forgot|otp`), `email`, `password`, `loading`, `message`, `error`, `otpStep`, `code`, `sentTo`, `cooldown`, `qi`. תוספות:

- `role` (`coach|player|parent`) — מ-1a, נשמר ב-`localStorage('signup_role')`, מועבר כ-prop.
- `fullName`, `club`, `consent` — שדות 1c.
- `sentStep` — כדי ש-1f יהיה מסך ולא באנר.
- `strength` — נגזרת מ-`password`, לא state נפרד.
- `joinCode` — ב-`JoinWithCode`, נכתב ל-`localStorage('pending_join_code')`.

**קריאות Supabase — כולן קיימות:** `signUp`, `signInWithPassword`, `resetPasswordForEmail({ redirectTo: origin + '?reset=true' })`, `signInWithOtp`, `verifyOtp({ type: 'email' })`, `updateUser({ password })`. **אין קריאה חדשה ואין שינוי סכימה.** שם מלא/מועדון דורשים החלטה על יעד השמירה (metadata או טבלת פרופילים) — ראה למטה.
